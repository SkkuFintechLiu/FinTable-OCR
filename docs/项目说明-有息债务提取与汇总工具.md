# 有息债务数据提取与汇总工具

## 一、项目概述

"有息债务数据提取与汇总工具"是一套面向债券研究、信用分析和财务数据整理场景的本地化 Web 应用。系统能够从债券年度报告、募集说明书等 PDF 文档中，自动识别文档类型、发行人和年度口径，定位"发行人合并口径有息债务结构情况"相关表格，提取并统一整理有息债务数据，支持人工核验、在线修订、来源追溯和 Excel 导出。

项目采用前后端一体化的轻量架构，既可以通过 Python/Flask 在本地运行，也可以使用 Docker 部署，还提供 macOS App 和 Windows 可执行文件的打包入口，适合个人分析、研究团队内网或受控环境使用。

## 二、解决的问题

债券报告中的有息债务信息通常分散在不同格式、不同章节和不同版式的 PDF 中，人工整理容易出现定位耗时、年度口径混淆、单位不一致、表格跨页和扫描件无法读取等问题。本项目通过"自动抽取 + 结果核验 + 可追溯导出"的方式，减少重复录入工作，并为每项数据保留原始文本、来源文件、页码和解析器等辅助信息。

## 三、核心功能

### 1. PDF 批量上传与处理队列

支持拖拽或选择多个 PDF 文件上传，单次最多 50 个。对文件头进行 PDF 格式校验，并为每个文件创建独立处理任务。在队列中展示文件名、文档类型、发行人、年份、处理状态、置信度和目标页码。支持对已识别类型进行人工修正并重新解析。支持从 uploads 目录批量重新提取样本文件。

### 2. 文档类型与元数据识别

自动区分年度报告和募集说明书。从 PDF 页眉、封面和正文中提取发行人名称。对发行人名称进行规范化和别名合并，减少同一发行人因名称差异产生重复记录。从文档内容和文件名中识别年度信息。

### 3. 有息债务表格提取

系统围绕以下六类标准字段建立统一数据模型：

| 标准字段 | 含义 |
|---|---|
| 信用类债券 | 公司信用类债券等债券融资 |
| 银行贷款 | 银行贷款或银行借款 |
| 非银行金融机构贷款 | 非银行金融机构、非银等贷款 |
| 其他有息债务 | 其他融资或其他有息负债 |
| 合计 | 有息债务金额合计 |
| 1年以内 | 一年以内到期或短期部分 |

年度报告解析器支持目录定位、关键词定位、表格候选提取、行列映射和单位换算。募集说明书解析器支持多年度列识别、年度口径筛选、表格定位和跨年度数据整理。主要使用 pdfplumber 进行文本与表格抽取，并使用 PyMuPDF 进行 PDF 读取、文本兜底和页面信息处理。对元、万元等单位进行标准化，统一输出为亿元口径。对无法提取、格式异常或单位不明确的字段保留原始文本，并标记相应状态。

### 4. 扫描件 OCR 兜底

对缺少可提取文本的扫描型 PDF 提供 OCR 处理路径。支持 PaddleOCR，以及通过环境变量配置的外部 OCR 引擎（如百度 Unlimited-OCR 的 SGLang/vLLM 远程服务或本地 Transformers 部署）。OCR 处理使用全局锁，默认将 PDF 解析并发限制为 1，以降低多个 OCR 会话同时运行造成的内存压力。支持定位模式和提取模式，通过较低成本的页面定位减少全文 OCR 范围。

双 OCR 引擎对照策略（环境变量 `OCR_STRATEGY` 控制）：
- `dual_merge`（默认）：PaddleOCR 与 Unlimited-OCR 并行识别，通过多维质量评分（有效字符占比、字符多样性、表格关键词命中、长度、行数、平均行长）做质量门控融合；一方得分显著低于另一方 70% 时直接丢弃劣质结果，确保准确率不下降
- `dual_best`：双引擎运行后取质量评分更高的输出
- `paddle_only`：仅使用 PaddleOCR（与升级前基线一致）
- `unlimited_only`：仅使用 Unlimited-OCR

Unlimited-OCR 接入方式：
- 远程 SGLang/vLLM：设置 `UNLIMITED_OCR_ENDPOINT=http://host:port`，可选 `UNLIMITED_OCR_MODEL`、`UNLIMITED_OCR_IMAGE_MODE`（gundam/base）、`UNLIMITED_OCR_API_KEY`、`UNLIMITED_OCR_TIMEOUT`
- 本地 GPU：安装 `torch`、`transformers>=4.57`、`einops`、`addict`、`easydict`、`accelerate`，CUDA 可用时自动启用 `baidu/Unlimited-OCR` 模型

### 5. 汇总、核验与编辑

按"发行人 + 年份"聚合多份文件中的结果。对重复来源按任务置信度和处理时间进行选择，并在字段层面补充缺失值。Web 页面提供多年度宽表预览。缺失字段和异常字段使用颜色高亮。用户可以直接点击单元格编辑数值，失焦后通过 API 自动保存。点击处理队列中的文件可聚焦对应发行人行，便于核对来源。

### 6. 可追溯与可信度信息

每个任务及年度结果可以记录或展示：
- 来源文件；
- 目标页码；
- 解析器类型；
- 表格或页面的定位信息；
- 原始文本片段；
- 字段状态，如 ok、missing、invalid、unit_unknown；
- 任务级置信度和状态原因。

这些信息用于辅助人工复核，避免将自动抽取结果作为不可解释的黑盒数据。

### 7. Excel 导出

系统通过 openpyxl 生成 .xlsx 文件，当前导出工作簿包含：
- **宽表**：按发行人和年度展示六类标准字段，并附数据来源。
- **长表**：按发行人、年度、债务类型展开，包含数值、状态、置信度、页码、定位信息、解析器和原始文本。
- **错误日志**：集中列出缺失、无效或单位不明确的字段。
- **解析日志**：记录页码、解析器、定位信息和标题片段。

缺失字段在宽表中以黄色标记，异常或单位不明确字段以橙色标记，便于后续复核。

## 四、系统架构

```
用户浏览器
    │ HTTP
    ▼
Flask Web 服务（app.py）
    ├── 任务队列与并发控制
    ├── 文件上传、状态查询与结果编辑 API
    ├── 年度报告解析器
    ├── 募集说明书解析器
    ├── PDF 表格抽取与 OCR 模块
    ├── 发行人/年度元数据识别
    ├── 结果聚合与可信度计算
    └── Excel 导出模块
    │
    ▼
前端单页界面（HTML + Vanilla JavaScript + CSS）
```

## 五、代码模块说明

| 文件或目录 | 职责 |
|---|---|
| `app.py` | Flask 应用入口、API 路由、上传处理、异步任务编排和服务启动 |
| `modules/classifier.py` | 年度报告/募集说明书类型识别 |
| `modules/metadata.py` | 发行人、年份及页眉元数据提取与规范化 |
| `modules/annual_report.py` | 年度报告表格定位、解析和字段提取 |

| `modules/ocr.py` | OCR 引擎（PaddleOCR + Unlimited-OCR）、OCR 锁、定位/提取模式、质量评分与双引擎融合、OCR 配置 |

| `modules/excel_exporter.py` | 生成四工作表 Excel 文件 |
| `templates/index.html` | Web 页面结构 |

| `static/style.css` | 页面样式和状态视觉反馈 |
| `scripts/verify_samples.py` | 样本批量解析与回归验证 |

## 六、API 能力概览

| 接口 | 用途 |
|---|---|
| `POST /api/upload` | 上传一个或多个 PDF |
| `GET /api/tasks` | 获取全部处理任务 |
| `GET /api/status/<task_id>` | 获取单个任务的详细状态和提取结果 |
| `POST /api/reprocess_uploads` | 批量重新处理 uploads 目录中的 PDF |
| `PUT /api/tasks/<task_id>` | 修改文件类型并重新解析 |
| `DELETE /api/tasks/<task_id>` | 删除任务及对应上传文件 |
| `GET /api/data` | 获取按发行人聚合的数据 |
| `PUT /api/data/<issuer>` | 修改指定发行人的年度字段 |
| `DELETE /api/data/<issuer>` | 删除发行人聚合数据 |
| `POST /api/export` | 导出 Excel 工作簿 |

## 七、运行与部署

### 本地运行

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python app.py
```

默认访问地址为 `http://127.0.0.1:5000/`。

### Docker 部署

```bash
docker compose up --build
```

Docker 配置使用 Python 3.11，并默认设置单 PDF 解析并发、数值计算线程上限和 PaddleX 缓存目录。服务访问地址为 `http://localhost:5000/`。

### 独立软件

- **macOS**：执行 `packaging/build_macos.sh`，或双击项目提供的一键启动脚本。
- **Windows**：运行 `packaging/build_windows.bat`。

打包运行时使用独立的 `runtime_uploads` 目录；根据当前启动说明，软件退出时会清理该运行时目录。

### 启用 Unlimited-OCR（可选）

```bash
# 方式一：对接 SGLang/vLLM 远程服务
export UNLIMITED_OCR_ENDPOINT=http://127.0.0.1:10000
export UNLIMITED_OCR_IMAGE_MODE=gundam   # 或 base（1024分辨率）

# 方式二：本地 GPU 直接运行（需要 CUDA）
pip install torch transformers==4.57.1 einops addict easydict accelerate
python app.py
```

可选策略切换：`export OCR_STRATEGY=dual_best`（双引擎择优） / `paddle_only` / `unlimited_only` / `dual_merge`（默认，融合补齐）。

## 八、数据与安全边界

- 当前聚合结果主要保存在进程内存中，服务重启后需要重新处理文件。
- 上传文件以 UUID 形式保存，默认存放于项目的 `uploads` 目录；打包运行时使用独立运行目录。
- 应用适合本地或受控局域网环境，当前未内置用户认证和细粒度权限管理。
- 生产部署时应结合反向代理、访问控制、上传目录权限和网络隔离策略使用。

## 九、项目特点与适用价值

- **面向具体业务口径**：围绕有息债务结构六项字段设计，减少通用 OCR 工具带来的二次整理成本。
- **兼容多种 PDF 场景**：同时覆盖结构化文本 PDF、复杂表格 PDF 和扫描件 PDF。
- **自动化与人工核验结合**：自动处理大批量文档，同时保留编辑、缺失标记和来源信息。
- **结果可解释**：通过页码、原文片段、解析器和错误日志支持复核。
- **部署灵活**：支持本地运行、Docker、macOS App 和 Windows 可执行文件。
- **OCR 可扩展**：基于可插拔引擎抽象，已集成 PaddleOCR 与 Unlimited-OCR，并保留接口以继续新增其他 OCR 工具，通过质量评分和策略组合保证准确率不下降。
